# Phase-0 API assumptions and decisions

This file separates behavior confirmed in current official documentation from account-specific behavior measured by the probes. Probe outcomes are filled in after the owner supplies a key; a failed product-access probe is a valid finding.

| Item | Confirmed behavior | Doc URL | Decision |
|---|---|---|---|
| Universal Streaming transport | v3 uses `wss://streaming.assemblyai.com/v3/ws`, binary PCM audio, `Begin`/`Turn`/`Termination` events, and a JSON `Terminate` message. | https://www.assemblyai.com/docs/streaming/guides/streaming_transcribe_audio_file | Use two independent v3 sessions and pace 100 ms PCM16 chunks in real time. |
| Streaming model and keyterms | Current examples use `universal-3-5-pro`; `format_turns` and JSON-encoded `keyterms_prompt` are query parameters. | https://www.assemblyai.com/docs/streaming/guides/streaming_transcribe_audio_file and https://www.assemblyai.com/blog/streaming-keyterms-prompting | Probe the current model with the four required keyterms. |
| Streaming keyterm limit | Streaming accepts up to 100 keyterms, each at most 50 characters. Current SDK examples may call the same current generation `u3-rt-pro`; the raw-v3 migration documentation and this account's successful probe use `universal-3-5-pro`. | https://www.assemblyai.com/docs/coding-agent-prompts and https://www.assemblyai.com/docs/streaming/guides/v2_to_v3_migration_js | Keep the account-tested `universal-3-5-pro` raw-WebSocket identifier for Phase 2. Prioritize organization and household names, add lexicon phrases of at most three words, and cap the request at 100 terms. |
| Streaming channel separation | AssemblyAI recommends a separate streaming session for each audio channel. | https://www.assemblyai.com/docs/streaming/label-speakers-and-separate-channels | One caller session plus one senior session supplies deterministic speaker labels. |
| Voice Agent connection | Inline agents connect to `wss://agents.assemblyai.com/v1/ws`, authenticate with a Bearer header, and start with `session.update`. | https://www.assemblyai.com/docs/voice-agents/voice-agent-api/session-configuration | Use one dynamic inline session; do not create a persistent agent during this probe. |
| Voice Agent audio | `audio/pcm` is base64 PCM16 mono at 24 kHz; approximately 50 ms chunks are recommended. | https://www.assemblyai.com/docs/voice-agents/voice-agent-api/audio-format | Preserve the required 16 kHz fixture and resample a copy in memory to 24 kHz for this API only. |
| Voice Agent events and text turns | The server can emit user/agent transcript events, `reply.audio`, and `tool.call`; `conversation.message` injects a text-only turn and `reply.create` requests a response. | https://www.assemblyai.com/docs/voice-agents/voice-agent-api/events-reference | Capture every event name, audio presence, transcripts, tool arguments, and whether text injection is accepted. |
| Batch multichannel | `multichannel=true` returns channel-numbered utterances and is supported across languages, regions, and models. | https://www.assemblyai.com/docs/pre-recorded-audio/transcribe-multiple-audio-channels | Upload one 30-second stereo fixture and keep channel separation enabled. |
| PII redaction | Text and audio redaction use `redact_pii`, policies, and `redact_pii_audio`; WAV redacted audio is available from the redacted-audio endpoint for 24 hours. | https://www.assemblyai.com/docs/guardrails/redact-pii-from-transcripts | Request entity-name substitution and WAV audio redaction while also testing entities and sentiment. |
| LeMUR status | The former LeMUR migration URL now redirects to the OpenAI-compatible LLM Gateway quickstart. | https://www.assemblyai.com/docs/llm-gateway/migration-from-lemur and https://www.assemblyai.com/docs/llm-gateway/quickstart | Keep `probe_lemur.py` for phase compatibility, but test the documented LLM Gateway successor using the redacted transcript. |
| Account: Universal Streaming | PASS. Both concurrent sessions produced text; median first-arrival word lag was 834 ms. Observed events: `Begin`, `SpeechStarted`, `Turn`, `Termination`. | https://www.assemblyai.com/docs/streaming/message-sequence | The under-1500 ms gate passes; keep separate caller and senior sessions. |
| Account: Voice Agent | PASS. Resolved input was PCM16 mono 24 kHz; user and agent transcript events and reply audio were emitted; `conversation.message` was accepted; `take_message` was called. | https://www.assemblyai.com/docs/voice-agents/voice-agent-api/events-reference | Set `AGENT_BACKEND=voice_agent`. |
| Account: batch and incident JSON | PASS. Multichannel, two audio channels, all six PII policies, WAV audio redaction, entity detection, and sentiment analysis were accepted. Redacted text and the five-key JSON incident object were returned; redacted audio reached `redacted_audio_ready`. | https://www.assemblyai.com/docs/guardrails/redact-pii-from-transcripts and https://www.assemblyai.com/docs/llm-gateway/quickstart | Use pre-recorded STT plus LLM Gateway for the post-call pipeline. |
| Account: Groq | SKIPPED because `GROQ_API_KEY` is empty. | https://console.groq.com/docs/openai | Keep Groq as a deferred Phase-3 fallback; it is not needed for the selected backend. |
